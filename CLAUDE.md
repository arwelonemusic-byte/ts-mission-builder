# TS Mission Builder

Web-based mission creation tool for Arma Reforger. Community members design a mission in the browser (map, factions, AI zones, briefing) and the tool generates a complete, workshop-ready mission addon as plain text files. Workbench is needed only to open the project once (regenerates `resourceDatabase.rdb` / missing `.meta`) and to publish.

## Repo layout

npm workspaces: `generator` (package `mission-gen`) + `web`. Root `npm install`; dev server: `npm run dev` in `web/` (localhost:3000); typecheck/build: `npm run build` in `web/`.

- `generator/lib.mjs` — pure generator library (`buildMissionFiles(mission)` → `{files, guids, addonDirName}`), runs in Node AND the browser. `generator/catalogue.mjs` — the GUID catalogue (terrains, factions, `ZONE_MODULES` UI list) + the `MODS` registry merge. `generator/mods/*.mjs` — per-mod content registries (currently `rhs.mjs`). `generator/generate.mjs` — CLI wrapper that builds the TS_WebSpike test mission (`node generate.mjs`; `--rhs` builds the TS_WebSpikeRHS variant exercising the mod path).
- `web/` — Next.js 16 + Tailwind v4, styled to match ts-ops-planner (full-bleed map, floating 360px panel, yellow `#f4db50` accent). `src/app/page.tsx` = the editor shell (step tabs Mission/Factions/Spawn/Zones/Markers/Brief + GENERATE, all state lifted here, localStorage key `ts-mission-builder-v1`); per-step panels in `src/components/panels/`; `src/components/MissionMap.tsx` = lean imperative Leaflet map (CRS.Simple with flipped-Y transformation, XYZ tile pyramids from `public/tiles/` — tiles required, no single-image fallback; lat=worldZ lng=worldX, 1 unit = 1 m); `src/lib/export.ts` = mission state → generator input (heightmap Y sampling) → File System Access API folder write (Chrome/Edge only); `src/lib/heightmap.ts` = bilinear sampler from ts-ops-planner **with a grid-registration fix (2026-08-04, engine-validated)**: pixel i sits at exactly i·cellSizeM (the extractor keeps every step-th terrain vertex), so px-per-metre = 1/cellSizeM — the original `(widthPx-1)/worldWidthM` mapping stretched the grid ~0.15% (Arland: last vertex 4090 m vs worldWidth 4096) and read terrain ~3 m south-west of the true point at mid-map, sinking slope-placed props ~1 m; after the fix the sampler matches Workbench `getHeight` to the cm on grid vertices (ts-ops-planner still carries the stretched mapping — port the fix if its heightmap use ever becomes precision-sensitive); **mission file (.json)** = the browser-agnostic escape hatch for the Chrome/Edge-only addon export — `downloadMissionJson`/`parseMissionJson` in `mission.ts` (Mission tab → Save/Load to file, plain Blob + `<a download>`, no File System Access API) let a Firefox user hand their mission to someone who can generate it. Both localStorage loads and file imports run the SAME `migrate()` in `mission.ts` — keep it additive and never let it throw or bail to `newMission()`: `page.tsx` writes the loaded mission straight back to localStorage, so a bail overwrites the user's save; `src/lib/terrains.ts` = 3 vanilla terrains (tile pyramids + heightmaps copied from ts-ops-planner).

## 3D view (2026-07-31)

`web/src/components/MissionMap3D.tsx` (~1000 lines, raw three.js ^0.184 + CSS2DRenderer, ported from ts-ops-planner's replay-only `MapClient3D` and made editable). Toggle = "3D" button in the shared top-right HUD cluster (`MapViewControls.tsx`, used by both views), desktop-only. Core editing works in 3D: place/select/drag individual spawn elements, zones, markers, QRF origins (multi-drop, live dashed line + distance pill); sectors render projected with a center-chip for select/move — **sector draw/resize/rotate stay 2D-only** (`armSectorDraw` auto-switches to 2D), and so does spawn-element rotation. Escape/placeMode/banner/panel flows are page-side and work unchanged.

- **Swap strategy (page.tsx)**: Leaflet stays mounted inside a `hidden` wrapper (its ResizeObserver → invalidateSize handles re-show) so 2D pan/zoom survives; 3D mounts on demand. Per-view API refs `mapApi2d`/`mapApi3d` + `mapApi()` accessor reading `view3DRef` — a single ref goes stale across toggles. Entering 3D captures the 2D viewport via `MapApi.getView()` → `initialView` prop.
- **Terrain** = one BufferGeometry, `seg = min(heightmapPx-1, 256)`, vertices from the shared sampler cache (`lib/terrainSampler.ts`, extracted from export.ts). Texture = `lib/tileComposite.ts`: the existing XYZ tile pyramid stitched into a ≤6144px canvas at runtime (deepest z that fits; missing edge tiles keep the `#0d0f11` fill; LRU cache of 3; key off `TerrainConfig` fields only — eden→everon/cain→kolguyev folder mismatch). No stitched JPEGs shipped.
- **Draped overlays hug the RENDERED mesh, not the raw heightmap**: `meshY()` interpolates the same decimated grid `buildTerrain` filled (triangle-exact against its diagonal split) + lift (lines 1.5 m, fills 0.75 m + polygonOffset, icons 1.5 m). `pickTerrain()` = analytic ray-march over that grid (bisect on sign change) — cheap enough for pointermove picking; used for everything (clicks, drags, MMB pivot, wheel anchor, coords readout). `Raycaster.intersectObjects` only for the few spawn-bundle pick quads.
- **Icons/handles are CSS2DObjects reusing the exact 2D divIcon HTML** — builders extracted to `lib/overlayHtml.ts` (markerHtml/zoneDotHtml/originBadgeHtml/distancePillHtml/sectorChipHtml/pingHtml; MissionMap wraps them in L.divIcon). Screen-constant for free; interactive ones set `pointerEvents:auto` (CSS2D layer is `none`) so their pointer events never reach the canvas — camera pan suppressed structurally. Shared drag controller: 4 px click-vs-drag threshold, pointer capture, live redrape via in-place position-buffer refills, commit on pointerup (React state → full `syncOverlays()` clear-and-rebuild, same dep list as the 2D redraw effect).
- **Canvas clicks**: LMB up with < 5 px movement → `pickTerrain` → `onMapClick` — feeds the whole page-side placeMode dispatcher with zero page changes (no suppressClickRef needed in 3D).
- **Gotchas fixed the hard way (don't regress)**: (1) the hidden 2D map must SKIP the focus effect and return null from `getView` when its size is 0 — fitBounds on a display:none map lands on a garbage max-zoom view that then poisons the 3D handoff; (2) after the async sampler resolves, lift the camera rig (target+eye) by the terrain height at the target — the initial framing assumes y=0 and a close-in view over high ground otherwise starts INSIDE the terrain (black screen); (3) `initialView` is consumed once via a ref and bounds-checked — a terrain switch while in 3D re-runs setup with coords from the previous world.
- v2 candidates: sector draw/resize/rotate in 3D, AO outside-darkening (2D donut doesn't port to a draped mesh — outline only), zone hover tooltips, 3D camera pose persistence across toggles, touch controls.

## Validated architecture facts (don't re-derive)

- **Offline generation works.** Addon = `addon.gproj`, `Missions/*.conf(+.meta)`, `Worlds/*.ent` (3-line `SubScene { Parent "{GUID}worlds/..." }`) `(+.meta)`, `Worlds/*_Layers/*.layer` (text, LF, UTF-8 no BOM). `resourceDatabase.rdb` is binary — never write it; Workbench recreates it on open/close.
- **Self-assigned GUIDs are accepted.** Random/timestamp 16-hex in hand-written `.meta` files works (validated in Workbench + playtest). Keep resource GUIDs stable across generator re-runs.
- **Clean resource override** = same relative path as the original + `.meta` declaring the ORIGINAL resource's GUID. For prefab overrides, mirror Workbench output (see `addons\Operation NewOp` examples): same parent ref AND same root `ID` as the original file, declare only changed components using the base's component-instance GUIDs (quoted: `SCR_Foo "{GUID}"`). Engine layers deltas — the toolkit's other components survive. Four standard overrides per mission: TS_MissionLoadouts.conf `{2B1F00FB4CED5910}` (loadout list — toolkit default is empty, all entries are new members with fresh GUIDs), LoadoutCrates_Conf.et `{897A36FA3D0A19F8}` (faction affiliation only), TS_CustomArsenal.conf `{DDDE97723E57CC62}`, Briefing.conf `{66D418A7AFBF6FEB}` (reuse the toolkit's entry instance GUIDs for the 3 default sections ids 0-2; user-added extra sections get fresh GUIDs, sequential `m_iEntryID` from 3, `m_eJournalEntryType Custom` + editable `m_sCustomEntryName` — Foxhound pattern; multi-line text = quoted lines joined by `\` + newline).
- **Component overrides in layers/prefabs must reuse the base prefab's component-instance GUIDs** — never mint fresh GUIDs for them. Fresh GUIDs only for NEW array members / nested objects.
- **Mod Defaults standard** (per spec): 6 layers (default/AO/Spawn/Markers/QRF/Props; empty `.layer` files are valid; +Objectives.layer since 2026-07-31 — see the Objectives section); FactionManager callsigns/group presets on the playable faction come from `mission.groups` (`{name, size}[]`, 1–8 groups, size 1–9; UI = Squads section in PlayersPanel), default 1'1–1'4 + 1'6 @ 9/9/9/9/3 when absent — squad-name entry [i] MUST positionally reuse `F.squadBase[0..3]` GUIDs (then `squadFifth` at index 4, minted GUIDs beyond), all 4 squadBase overrides are always emitted even with fewer groups (fallback names `1'N` so overflow auto-groups don't pick up vanilla "3"/"4"), quotes in names are escaped to `'`; `m_sCallsignGroupFormat "%3"`, `m_bIsAssignedRandomly 0` on ALL factions' `SCR_FactionCallsignInfo` (default 1 hands out squad names in random order); GameModeSF spawn logic WITHOUT `m_sForcedFaction`; LoadoutManager entries Arsenal/Rifleman (names inherited from `LoadoutManager_Base.et`, set only resource + faction); Spawn layer = faction spawn point + AreaSpawn→LayerCrates/LayerVehicles slots + optional FARP `{0C16FFB1B07F4A89}` (plain placement); MVP plugin set = AIPatrol, MountedPatrol, Fortification, QRFFoot, QRFMounted, SmartGarrison. Every generated Area sets `m_bDynamicDespawn 1` + `m_iDynamicDespawnRange` = zone radius + 600 (was +400 until 2026-08-02).
- All catalogue GUIDs (terrains arland/eden/cain + navmeshes, faction entries, callsign infos, vanilla squad-name members, characters, vehicles, arsenal items) are ground-truthed in `generator/generate.mjs` — extend, don't re-harvest.

## Mission thumbnails

User-uploaded image → one `.edds` driving all three mission-header fields (`m_sIcon`/`m_sLoadingScreen`/`m_sPreviewImage`). **`.edds` is written entirely offline — Workbench converts nothing** (validated end-to-end 2026-07-31: a file written by `web/src/lib/edds.ts` registered, decoded and thumbnailed in Workbench).

- **Format** = standard 124-byte DDS header + ASCII `ENF1` at `0x24` (reserved1[1] — present in all 4377 vanilla + 67 community `.edds` scanned) + standard DX10 header + **Enfusion mip table at `0x94`** (one 8-byte entry per mip: 4-byte tag `COPY` (raw) / `LZ4 ` + 4-byte stored size, ordered **smallest mip first**) + payloads concatenated in table order. The GUID is NOT in the binary — the sidecar `.edds.meta` is the sole source, so self-assigned GUIDs work exactly like `.conf`/`.ent`. Both `.meta` and source images are stripped at pak time (vanilla paks: 28956 `.edds`, 0 `.png`, 0 `.meta`).
- **We emit BC7 mode 6** (dxgi 99 `BC7_UNORM_SRGB` — the most common vanilla format; all mips `COPY`, so no LZ4 needed; floor-halved mip chain matching Workbench level-for-level). 1920×1200 → 2.93 MB, PSNR 47 dB, ~370 ms. Uncompressed BGRA (dxgi 91) also loads fine and is 11.7 MB. `pitchOrLinearSize` = top-mip byte size in both cases.
- **Ship the source `.png` next to the `.edds`.** An orphan `.edds` loads, registers and thumbnails fine, but Workbench's `TextureImportTool` reports `Source file not found` (this is the editor's reimport path, not the loader). Sources cost nothing in the published pak. Write the `.png` BEFORE the `.edds` so the `.edds` isn't treated as stale.
- **One Workbench launch is enough to publish — no restart.** A `RESOURCES (E): Wrong GUID ... {0000000000000000}` line appears only when textures are dropped into a project whose `resourceDatabase.rdb` was already built without them. Generated addons ship no rdb, so their first full scan registers our GUID cleanly (verified by wiping the rdb: clean log, GUID present in the rebuilt rdb).
- **Compositing** (`web/src/lib/thumbnail.ts`; template `web/public/thumbnail-template.png`, 1920×1200): photo cover-fitted UNDER the template, mission name in Roboto Slab Bold **140px on baseline y=1041**, ink-left **x=154**. Position by measured INK, not nominal metrics — cancel the first glyph's side bearing via `actualBoundingBoxLeft`, and do NOT anchor to cap height (lowercase ascenders like `h` sit ~7px above caps, so cap-anchoring lifts any name containing one). A leading "Operation " is stripped since the template already prints it; long names shrink to 70px before overflowing. Uploads are stored as JPEG data URLs (a 1920×1200 PNG would blow the localStorage budget and the `.json` handoff).
